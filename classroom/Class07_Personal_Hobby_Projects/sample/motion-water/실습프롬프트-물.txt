내용: [숫자로 보여 줄 이야기 한 가지를 적으세요. 가진 숫자가 있으면 함께 적으세요. 예: 우리 팀 3분기 회고 / 신입 온보딩 첫 달 / 고객 문의 줄이기]

첨부한 motion-template-water.html을 그대로 복사해서 시작하세요. 이 파일은 참고 이미지가 아니라 작동하는 원본입니다. 한 장에 큰 숫자 하나로 이야기를 끌고 가는 한 장짜리 HTML 발표 자료입니다. 짙은 남색 바탕(#0a0f14)에 회백색(#d4d1ce) 큰 숫자가 주인공이고, 그 위를 물 덩어리가 떠다니며 글자를 굴절시킵니다. 넘기면 물이 왼쪽에서 오른쪽으로 쓸고 지나가며 다음 장이 나오고, 한 장에서는 물이 얼음처럼 굳습니다. 위 내용란에 맞게 자료만 바꿔 실제 presentation.html 파일로 완성하세요. 시청자는 내용란만 바꿉니다. 첨부 파일에 든 글과 숫자는 예시입니다. 모두 내용란에 적힌 이야기로 바꾸세요. 내용란이 대괄호 그대로이면 대괄호 안 예시 가운데 첫 번째로 만드세요.

[편집 범위: 반드시 지키세요]
1. 원본의 편집 계약 주석(PRESENTATION_EDIT_CONTRACT)과 presentation-data JSON을 먼저 읽으세요. 파일을 읽지 못하면 중단 사유를 말하세요.
2. 수정할 곳은 <script type="application/json" id="presentation-data"> 안의 JSON 한 곳뿐입니다. 속성 순서가 달라도 이 id의 JSON 본문을 찾으세요. CSS, 실행 JavaScript, HTML 구조, 글꼴, 라이선스, 클래스, ID, data-* 속성은 한 글자도 바꾸지 마세요. 도구의 레이아웃 검사를 맞추려고 구조나 속성을 덧붙이지 마세요. 일반 HTML 파일이며 PPTX용 슬라이드로 변환하거나 새 포장 파일로 감싸지 마세요.
3. JSON 파서로 읽고 객체를 수정한 뒤 JSON 직렬화기로 저장하세요. 정규식으로 개별 문장이나 코드 괄호를 바꾸지 마세요. 원본 JSON의 키 이름, 필수 필드, 자료형을 그대로 지키세요. 배열 길이는 계약의 schema가 허락하는 범위에서만 바꾸세요. 실행 코드나 함수 문자열을 JSON에 넣지 마세요. 문자열의 <는 \u003c로 이스케이프하세요.
4. 내장 글꼴의 거대한 base64는 복사로 보존하고 모델에 읽어 들이거나 다시 출력하지 마세요. 외부 리소스는 추가하지 마세요. 최종 결과는 인터넷 연결 없이 작동하는 단일 HTML입니다.

[주제에 맞게 바꿀 내용]
이 자료는 장마다 숫자 하나를 크게 보여 줍니다. 숫자 위에는 이름과 단위, 아래에는 한 줄 결론과 흐린 출처가 놓입니다.
- slides: 3~9장입니다. 주제를 보여 줄 숫자를 장마다 하나씩 고르세요. 한 장에 숫자를 둘 넣지 말고 장을 나누세요. 앞 장에서 뒤 장으로 이야기가 이어지게 순서를 정하세요.
- num: 화면 가운데 큰 숫자입니다. 큰 숫자 글꼴이 영문 전용이라 숫자, 영문, 기호만 쓰고 6자 이하로 쓰세요(한글, 빈칸 불가). 예: 412 / 3.2 / -18 / 4.6
- unit: 단위입니다(8자 이하, 한글 가능). 화면에서는 label 첫 마디 뒤에 괄호로 붙어 나옵니다. 예: label 「처리한 고객 문의 · 7~9월」과 unit 「건」은 「처리한 고객 문의(건) · 7~9월」로 보입니다. label에는 단위를 다시 쓰지 마세요. 단위가 없으면 빈 글 ""로 두세요.
- label: 숫자 위 왼쪽에 놓이는, 이 숫자가 무엇인지입니다(30자 이하). 재는 대상과 기간·조건을 · 로 이어 쓰세요. 예: 처리한 고객 문의 · 7~9월
- line: 숫자 아래 한 줄 결론입니다(30자 이하). 숫자를 되풀이하지 말고 그 숫자가 뜻하는 것을 「~요」로 끝나는 쉬운 한 문장으로 쓰세요. 나쁜 예: 「12건을 출시했어요」(숫자를 되풀이함). 좋은 예: 「만든 것보다 고친 게 더 많았어요」. 예 문장을 그대로 가져다 쓰지 말고 내용란 이야기에 맞게 새로 쓰세요.
- cite: 맨 아래 흐린 출처 줄입니다(80자 이하).
- ice: true인 장은 넘김이 끝나면 물이 얼음처럼 굳고 갈라지는 소리가 납니다. 멈춘 것, 굳은 것, 막힌 것을 보여 주는 숫자 한 장에만 true로 하고 나머지는 false로 두세요. 맞는 숫자가 없으면 모두 false로 두세요.
- title: 화면 위 왼쪽에 「brand / title」로 나오는 발표 제목입니다(30자 이하). 원본 「숫자로 보는 물」처럼 무슨 이야기인지 한눈에 알 수 있는 짧은 말로 쓰세요.
- brand: 회사나 팀 이름입니다(16자 이하). 내용란에 없으면 이름을 지어내지 말고 주제를 줄인 말을 쓰세요. PAPERLOGY를 남기지 마세요.
- topic은 주제를 40자 이하로 적으세요. ui의 다섯 칸(다음, 이전, 소리, 소리 켬, 소리 끔)은 그대로 두세요.
- 숫자: 내용란에 숫자가 있으면 그 숫자를 쓰세요. 없으면 주제에 맞는 예시 숫자를 만들고 그 장의 cite를 「예시 숫자입니다.」로 시작하세요. 공개 자료의 숫자는 이번 작업에서 실제로 열어 확인한 것만 출처와 함께 쓰세요. 논문, 조사, 기관, 링크를 지어내지 마세요. 예시 숫자에는 「사내 기록」, 「회의록」 같은 출처를 덧붙이지 마세요.
- 말투: 화면에 나오는 글은 옆 사람에게 말하듯 쉬운 「~요」 말투로 쓰세요. 책에서나 쓰는 말(한 해, ~하는 것이다)과 숫자나 물건을 사람처럼 쓰는 표현(고집이 세다, 떠난다)은 쓰지 마세요. 소리 내어 읽었을 때 어색하면 고쳐 쓰세요.
- 원본 주제(물)의 낱말과 출처(굴절률, 밀도, 표면장력, IAPWS, NIST, USGS 등)를 남기지 마세요. 글자 수 제한(maxChars)을 지키고 한 문장에 한 뜻만 담으세요.

[완료 전 확인]
- JSON을 다시 읽어 파싱 성공과 계약의 schema, maxChars를 확인하세요. num이 숫자, 영문, 기호만으로 되어 있는지, ice가 true인 장이 한 장 이하인지 확인하세요.
- JSON 본문만 같은 표식으로 가린 원본과 결과의 나머지 바이트가 정확히 같은지 대조하세요. 다르면 JSON 밖 변경을 원본으로 되돌리세요.
- 실제 브라우저가 있으면 직접 열어 「자료 설정을 확인해 주세요」 화면이 뜨지 않는지 보고, 스페이스로 마지막 장까지 넘김, ←로 되돌림, 얼음 장, 소리 켬·끔(S)을 확인하세요. 1366×768, 1920×1080에서 큰 숫자와 글이 잘리거나 겹치지 않는지 확인하세요. 검사하지 못한 항목은 검증됐다고 쓰지 마세요.
